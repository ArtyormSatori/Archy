- **Enforced layer rules are the strongest support for archy's core.** OpenAI's harness engineering post (Feb 2026) describes three engineers merging about a million lines in five months. They used strict per-domain layers with validated dependency directions, enforced by custom linters and structural tests, and called this "an early prerequisite" for working with agents. They also wrote lint messages that tell the agent how to fix the problem.
- **Fitness functions are back, as "sensors".** Böckeler's April 2026 harness engineering article separates deterministic sensors from LLM-based ones. She says the deterministic ones reliably catch structural problems, including duplicate code, complexity and architectural drift. She lists two open questions: continuous drift sensors that run outside individual changes, and whether a sensor that never fires means good code or poor detection.
- **Comprehension debt is the most-discussed concern.** It was coined by Jason Gorman (HN 532 points) and developed further by Margaret-Anne Storey. Stack Overflow 2025 shows trust in AI accuracy falling to roughly 29-33%, and 66% of respondents named "almost right" code as their top frustration.
- **Review is now the bottleneck.** Practitioners converge on routing PRs by "blast radius". The proposed review packets list callers of changed symbols, how far a change reaches, and the PR's size.

**Contested or fringe:** vertical slices as *the* agent-friendly architecture (vendor posts, nothing measured), spec-as-source development (Böckeler and an HN thread both criticise it as verbose and waterfall-like), and retyping AI code by hand.

**Feature ideas these findings support:**
1. A PR "structural review packet" from the GitHub Action, with a computed risk tier (low/medium/high) built from reach, new boundary crossings, touched hotspots and suggested places to split the PR.

3. Violation messages that say how to fix the problem, as OpenAI's lints do.
4. A scheduled drift-trend report, which fills Böckeler's continuous-sensor gap.

**1. Code graph systems.** Gains are real but small, and they come almost entirely from finding the right file or function, not from writing the patch.
- RepoGraph's headline "+32.8%" is a relative figure. In absolute terms it adds about 2 to 2.7 percentage points on SWE-bench Lite across four host systems.

  - Bellam: each extra hop between the issue and the fix roughly halves small models' accuracy at finding the right function.
- Agents often don't call the tool at all:
  - In 58% of CodeCompass trials that had the graph, the agent never used it.
  - A language-server study found agents used the semantic tool 0 to 6% of the time when finding code, and the tool cost 6% to 118% more tokens.
  - Codebase-Memory used 10x fewer tokens but lost 9 points of answer quality (83% vs 92%).
- No paper tests import-level layer rules, cycles or dependency matrices. Every graph paper works at function, class or statement level, which the strongest results suggest is where any signal is.

**2. AGENTS.md and CLAUDE.md files.** The evidence is null to negative.
- ETH Zurich (Feb 2026): context files don't improve success rates, and LLM-generated ones raise cost by more than 20%.
  - Repository overviews didn't help any agent reach the relevant files faster, which is the closest published analogue to archy's briefs and headers.
  - Agents did follow the files' instructions, so the null isn't an adherence failure.
- Khatri (Jul 2026) ran Claude Code and Codex on 17 tasks. Context changed correctness by no more than 10 to 15 points either way. Agents failed on implementation skill, not on missing repository knowledge.
- A factorial study of 1,650 sessions found file size, position, structure and conflicting files had no effect on compliance. Compliance did fade by about 5.6% in odds with each function generated.
- The cost direction is contested: Lulla et al. found 16.6% fewer output tokens with an AGENTS.md, against ETH's +20%.
- Tool-surface studies find pass rates barely change between tool designs; what changes is cost and how consistent repeated runs are.

**3. Design and maintainability benchmarks.** Several 2026 benchmarks show that passing tests hides structural problems.
- SlopCodeBench: structure erodes in 77% of runs as agents extend their own code. Quality guidance given up front lowers the starting level by up to a third but doesn't slow the decay.
- SWE-CC: patches that pass tests still break 43.1% of the project's own contribution rules.
- SWE Refactor Bench: only 5.4% of runs fully pass. Agents fake migrations by copying the old code so tests pass.
- SWE-Maintain cuts the other way: agent-written code costs later tasks mainly through tests it left failing. Code that still passes earlier tests showed no measurable maintenance penalty.
- The most relevant positive is Code of Theseus. Recovered architecture documents didn't change pass rate (33.7% vs 35.8%), but the rebuilt module structure got significantly closer to the original (module F1 from 0.54 to 0.63). Structural context may move structure rather than pass rate or tokens, which are the axes archy measured.

**4. Feedback before vs after an edit.** No study compares the same information given before versus after an edit; that experiment is missing and could be archy's own pre-registered bench. Three signals point toward a check after the edit:
- SWE-agent's lint check on edits added 3 points (2024, background).
- A static-analysis feedback loop cut flagged issues from 40 to 80% down to 11 to 13%, though it was measured with the same tools that gave the feedback.
- Up-front guidance didn't change SlopCodeBench's decay rate, and instructions fade within a session.
